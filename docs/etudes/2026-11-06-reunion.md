# La Réunion et Nommer : conception (06/11/2026, #15)

Conception à coder sans re-concevoir. Fait foi pour le #15 ; le plan
(`../plan.md`) et les décisions du registre (« Quiz de La Réunion »,
« Nommer », « Contenu », « Langue », « Hébergement », « Points et
classement », « Classements », « Toucher sur la terre ferme ») priment en
cas d'écart. Fin du ticket : 24 communes jouables au doigt sur le site et
l'APK, données vérifiées par test en CI.

Résumé des choix :

- données : un script à part `geodata/reunion.mjs`, sorties dans
  `public/geo/reunion/` (topologie, attributs, noms, sources), ~15 Ko
  compressés, chargées au choix de la série seulement ;
- carte de l'île : la `Carte` SVG existante, paramétrée par un **cadre**
  (projection Mercator ajustée à l'île, zoom 1 à 8, sans pastilles), dans
  un second hôte `#carte-ile` posé sur le monde ; le monde ne change pas,
  quel que soit `?rendu=` ;
- bascule : un **terrain** (`monde` | `reunion`) par série ; un service
  `Terrains` (main.ts) charge et montre le terrain ; `ctx.carte` reste le
  monde (explorer, saisie, pilote de mesure) ;
- Nommer : module pur `src/vues/qcm.ts` (leurres, partie), vue
  `src/vues/nommer.ts` appelée par Toucher, interrupteur Localiser /
  Nommer en tête du départ ;
- Chrono : épreuve `chrono:localiser:reunion` (24 questions), échelle du
  barème par terrain (5 km), `VERSION_BAREME` inchangé (= 1), règles :
  taille 24, général 414.

## 1. Données

### Script

- **Nouveau fichier `geodata/reunion.mjs`**, lancé par `npm run
  geodata:reunion` (ajouter le script à `package.json`). **Ne pas toucher
  `geodata/build.mjs`** : son empreinte SHA-256 est dans
  `public/geo/sources.json` (`traitement.entrees`) et
  `tests/donnees.test.ts` (« sorties à jour ») échouerait jusqu'à un
  `npm run geodata` complet, qui demande les sources Natural Earth
  (absentes du worktree : `geodata/raw/` n'existe que dans le dépôt
  principal).
- Aides géométriques (sens de d3, point intérieur polylabel, emprise,
  aire) : copier celles de `build.mjs` (`polygones`, `pointInterieur`,
  `emprise`, `km2`) dans un module `geodata/outils.mjs` que seul
  `reunion.mjs` importe (`build.mjs` lance `main()` à l'import, il ne
  s'importe pas). À fusionner au prochain changement de `build.mjs`
  (non retenu maintenant : il faudrait tout regénérer).
- **Verrou à part : `geodata/reunion.lock.json`**, même forme que
  `sources.lock.json` (`{ "<cle>": { telecharge_le, fichiers: { chemin:
  sha256 } } }`). Pas dans `sources.lock.json` : `build.mjs
  --maj-empreintes` le réécrit avec ses seules sources et effacerait la
  clé de l'IGN.
- Mêmes règles que `build.mjs` : téléchargement dans
  `geodata/raw/ign/…` (déjà ignoré par git), SHA-256 contre le verrou,
  refus d'une empreinte différente sauf `--maj-empreintes`, sans réseau si
  `raw/` est rempli, deux lancements identiques octet pour octet.
- **Source en paramètre**, en tête du script (l'agent qui la cherche la
  remplit) :

```js
const SOURCE = {
  cle: 'ign-admin-express',
  nom: 'IGN, ADMIN EXPRESS COG CARTO, communes',   // produit exact : à confirmer
  url: '<page du produit (data.geopf.fr ou geoservices.ign.fr)>',
  edition: '<AAAA-MM-JJ : date de l’édition IGN>',  // affichée dans l'appli
  licence: 'Licence Ouverte 2.0 (Etalab), mention de la source et de la date de mise à jour',
  fichiers: [{ chemin: 'ign/<nom>', url: '<url>' }], // .7z (archive par territoire REU) ou GeoJSON (WFS)
  champs: { id: 'INSEE_COM', departement: 'INSEE_DEP', nom: 'NOM' }, // WFS : code_insee, code_insee_du_departement, nom_officiel
  departement: '974',
};
```

- Lecture : `.7z` → `7z x` (présent sur le PC, `/usr/bin/7z` ;
  `execFileSync`, jamais en CI : les sorties sont versionnées), puis
  mapshaper `-i <shp> encoding=utf8 -filter 'INSEE_DEP=="974"' -proj
  wgs84` (l'archive REU est en RGR92 / UTM 40S, EPSG:2975, `.prj` lu par
  mapshaper). GeoJSON du WFS : pas de `-proj`, mais **vérifier l'ordre
  des axes** (WFS 2.0 en EPSG:4326 rend lat, lon : demander `CRS:84` ou
  contrôler). Garde-fou dans le script : toute coordonnée hors de
  lon 55,1–56,0 / lat −21,5–−20,8 → `echec`.
- Traitement :
  1. 24 entités exactement, id = code INSEE (chaîne, `97401` à `97424`),
     sinon `echec` ;
  2. remettre chaque polygone dans le sens de d3 (`polygones()` de
     build.mjs : aire > 2π → anneaux inversés) ;
  3. sur la géométrie **non simplifiée** : `superficie_km2`,
     `partie_max_km2` (aire géodésique `geoArea × R²`, R = 6 371,0088 km),
     `point` (polylabel du plus grand polygone, 5 décimales), `bbox`
     (`emprise()`) ;
  4. topologie et simplification par mapshaper, d'un seul calque (arcs
     partagés : pas de trou ni de recouvrement entre communes) :
     `-simplify visvalingam interval=40 keep-shapes` (40 m ≈ 2 px au zoom
     8, 0,2 px au zoom 1), `-o format=topojson quantization=1e5` (≈ 0,7 m
     sur l'emprise de l'île). Objet `communes`, propriété `id` seule,
     triées par id ;
  5. voisins : `neighbors()` de topojson-client sur la topologie finale
     (arcs partagés), triés ;
  6. vérifier qu'aucun polygone n'a disparu (comme build.mjs).
- Si la cible de poids (≤ 25 Ko compressés pour la topologie) est
  dépassée, monter `interval` (60, 80 m) ; si les côtes deviennent
  anguleuses au zoom 8, le baisser. Mesurer, noter le choix dans
  `sources.json` (`traitement.simplification`).

- `statut` toujours `jouable`, `micro` toujours `false` (le seuil des

  rien ne s'en sert.
- Noms : `NOM` de l'IGN, apostrophe typographique `’` comme CLDR
  (« L’Étang-Salé ») ; `normaliser()` (src/texte.ts) les rend
  équivalentes pour la saisie du J1b.
- `sources.json` :
  `{ sources: [{ nom, url, version: edition, edition, licence,
  telecharge_le, fichiers: [{ url, sha256 }] }], traitement: { outil:
  'mapshaper 0.6.110', simplification, quantification, entrees: {
  'geodata/reunion.mjs': <sha256>, 'geodata/outils.mjs': <sha256> } } }`.
- Aucun `preload` dans `index.html` (décision « Hébergement »).

## 2. Carte de l'île

### Choix : la `Carte` SVG, généralisée par un cadre

- Pas de classe à part : `Carte` (src/map/carte.ts) a déjà tout ce que
  l'île demande (d3-zoom sans rotation, `SuiviPointeurs`, `pick` /
  `noter` purs, `marquer`, `anneau`, `montrer` animé, `vise`,
  redimensionnement). Ce qui la lie au monde tient en cinq points, à
  paramétrer : la projection (`creerProjection`), le fond `.sphere` et la
  borne du déplacement (`limiter` sur la sphère), `fabriqueTraces(nom)`,
  `ZOOM_MAX` / `ZOOM_MAX_MONTRER`, l'`aria-label`. Une classe à part
  dupliquerait ~250 lignes de gestes et de marques.
- Pas de Canvas ni de WebGL pour l'île : elle ne tourne pas, 24 communes
  font quelques milliers de sommets, le SVG en mode `g` les repeint sans
  peine. **L'île est toujours en SVG `g`, quel que soit `?rendu=`** ; la
  carte du monde reste celle du rendu choisi, intacte.

### Interfaces (src/map)

`types.ts` :

```ts
/** Ce que la carte demande d'une zone (pays ou commune) : pick, noter, pastilles, cadrage. */
export interface Lieu {
  id: string; statut: Statut; superficie_km2: number; partie_max_km2: number;
  point: [number, number]; bbox: [number, number, number, number]; micro: boolean; voisins: string[];
}
export interface Pays extends Lieu { a2?: string; continent: string; sous_region: string }
/** `pays` : la zone, pays ou commune (nom de champ gardé : ~140 usages). */
export interface Entite<L extends Lieu = Pays> { pays: L; forme: Forme }
export type NomTerrain = 'monde' | 'reunion';
```

- `donnees.ts` : `DonneesCarte<L extends Lieu = Pays>` (`entites:
  Entite<L>[]`) ; tout le code du monde garde le défaut.
- `pick.ts` : `ContexteCarte.entites: readonly Entite<Lieu>[]` ;
  `pastilles.ts` : `tailleEcranPx`, `aPastille` sur `Lieu`,
  `calculerPastilles(entites: readonly Entite<Lieu>[], …)`. Aucun
  changement de comportement.
- `traces.ts` : `fabriqueTraces(creer: (l: number, h: number) =>
  GeoProjection, proj)` (la copie agrandie UNITE fois vient de
  `creer(1, 1)` ; d3-geo n'a pas de `copy()`). Le monde passe `(l, h) =>
  creerProjection(nom, l, h)`.
- `carte.ts` : `OptionsCarte.donnees: DonneesCarte<Lieu>` et
  `OptionsCarte.cadre?: CadreCarte` ; absent = le monde, comme
  aujourd'hui :


### Projection, zoom, apparence

- **Mercator** (`geoMercator().fitExtent([[12, 28], [l − 12, h −
  max(120, 0,3 h)]], emprise)`) : conforme, et sur 0,5° de latitude son
  échelle ne varie que de 0,35 % (1/cos φ entre 20,87° et 21,39° S) ;
  l'UTM 40S officiel ne se distinguerait pas à l'écran. Rotation nulle :
  `traceDirect` s'applique (55° E est loin de la coupure).
- La marge basse garde le sud (Saint-Pierre, Saint-Joseph,
  Saint-Philippe) hors des barres : barre de Toucher ~120 px, de Nommer
  ~210, du Chrono ~130. Sur 384 × 723 : cadre 360 × 478 px, l'île
  (64,5 × 57,3 km) y tient par la largeur, **5,6 px/km**, 320 px de haut.
  Le haut (28 px) laisse la mention de la source (§ 7).
- Zoom 1 à **8** (1 px ≈ 22 m ; ~8 km sur la largeur du téléphone) ;
  `montrer` borné à **4**. Déplacement borné à l'emprise de l'île élargie
  à l'écran (comme `limiter`) : rien ne bouge au zoom 1.
- **Pas de pastilles** (`pastilles: false`) : la plus petite commune, Le
  Port (~16,6 km², √ ≈ 4,1 km), fait **~22 px** au zoom 1 sur le
  téléphone (seuil des pastilles : 10 px), la suivante, Petite-Île
  (~34 km²), ~32 px. Test : chaque commune ≥ 15 px
  (`tailleEcranPx`) au zoom 1 sur 384 × 723 et 320 × 560.
- `pick` / `noter` : ceux de pick.ts, inchangés. Mer : `pick` → `null`,
  ou la commune dont la côte est à moins de 12 px (sondes, ≈ 2 km au
  zoom 1). `noter` : juste dans le tracé de la commune demandée (ou si
  `pick` la désigne) ; sinon `distance_km` = distance géodésique au bord
  de la commune demandée (`distanceAuBordKm`, jamais `null` sur l'île).
- `marquer` / `anneau` / `montrer` / `zoomerSur` / `ecran` : ceux de
  `Carte`, `ecran` = point d'étiquette (pas de pastille).
- Apparence : la palette existante. Hôte `#carte-ile.carte.carte-ile`,
  `background: var(--mer)` (pas de `.sphere`), communes `.pays`
  (`--terre`, traits `--frontiere` 0,6 px non mis à l'échelle), marques
  `.choisi` / `.juste` / `.faux` comme le monde. Ajouter
  `.anneau.choisi { stroke: var(--accent) }` (seul `.anneau.juste`
  existe ; le Canvas et le WebGL prennent déjà `marques[classe]`).
  Couleurs seulement dans `:root` (tests/style.test.ts).

## 3. Bascule de terrain

### Service `Terrains` (nouveau `src/terrains.ts`, DOM)

```ts
export interface Terrain {
  nom: NomTerrain;
  carte: CarteAffichee;
  donnees: DonneesCarte<Lieu>;
  /** Ids jouables (séries, leurres de Nommer), dans l'ordre des données. */
  jouables: readonly string[];
  /** Mention de la source affichée sur la carte ; null pour le monde (⚙). */
  credit: string | null;
}
export interface Terrains {
  readonly monde: Terrain;
  readonly actif: NomTerrain;
  /** Le terrain, chargé et rendu une fois (promesse gardée ; un échec ne reste pas en cache). */
  charger(nom: NomTerrain): Promise<Terrain>;
  /** Montre ce terrain, cache les autres (classe .carte-cachee, body[data-terrain]). */
  montrer(nom: NomTerrain): void;
  /** Le terrain s'il est déjà chargé (sans réseau). */
  deja(nom: NomTerrain): Terrain | null;
}
export function creerTerrains(o: { monde: Terrain; hoteMonde: HTMLElement; surToucher: OptionsCarte['surToucher'] }): Terrains;
```

- `charger('reunion')` : `chargerTerrain(REUNION)`, crée
  `div#carte-ile.carte.carte-ile`, l'insère **juste après `#carte`**
  (`hoteMonde.after(…)`, avant les barres des vues dans le DOM, donc
  dessous), le montre, puis `new Carte({ hote, donnees, projection:
  'monde' /* ignoré avec cadre */, rendu: 'g', cadre: cadreLocal(…),
  surToucher })` et `rendre()` ; `prechauffer()` sur ses formes ; ajoute
  la mention de la source (§ 7). Sans `gestes` : les mesures restent
  celles du monde.
- `montrer(nom)` : `hote.classList.toggle('carte-cachee', …)` sur chaque
  hôte, `document.body.dataset.terrain = nom`. CSS : `.carte.carte-cachee
  { visibility: hidden; }` — **visibility, pas display** : l'hôte caché
  garde sa taille (pas de retracé ni de `clientWidth` nul au retour),
  ne reçoit aucun toucher, et la règle de la Saisie (`body[data-vue=
  "saisie"] .carte`) cache les deux.
- `surToucher` des deux cartes : `vueActive?.toucher?.(x, y, ev)` comme
  aujourd'hui ; seule la carte visible reçoit des touchers, la vue note
  sur **sa** carte courante.

### main.ts

- Le monde : inchangé (chargement, rendu, relais WebGL, mesures,
  `prechauffer`). `const terrains = creerTerrains({ monde: { nom:
  'monde', carte, donnees, jouables: <ids jouables>, credit: null },
  hoteMonde: hote, surToucher })`.
- `ContexteVue` (src/vues/commun.ts) gagne `terrains: Terrains` ;
  **`ctx.carte` et `ctx.donnees` restent le monde** (explorer, saisie et
  tout code qui ne connaît pas les terrains).
- `router()` : `terrains?.montrer('monde')` avant `v.activer()` ; une vue
  qui veut l'île la remontre dans son `activer`. L'onglet Carte reste
  donc toujours sur le monde.
- `window.terramemo.carte` **reste lié au monde** (contrat du pilote de
  mesure : `zoomer`, `pastilles`, `dessin`, `webgl`, `perdreContexte`).
  Ajouts : `terrain(): NomTerrain` et `ile: AideCarte | null` (rempli au
  chargement de l'île : `pick`, `ecran`, `rect`, `transfo`, `zoomer`,
  `zoomerSur` ; `pastilles` → `[]`, `dessin` → `null`, `webgl` → `null`,
  `perdreContexte` → `false`). Factoriser la construction d'une
  `AideCarte` (fonction `aide(carte, hote)`).
- Rien de l'île au premier affichage : aucun fetch avant le clic sur la
  série (vérifié par smoke, § 8). Hors ligne sur le site : `charger`
  rejette, la vue l'écrit dans son départ et reste sur le monde. APK :
  `public/geo/reunion/` part dans `dist/` et dans l'APK, hors ligne
  compris.
- Pendant le chargement (~100–300 ms sur le réseau du téléphone) :
  boutons du départ désactivés, statut `chargement_terrain`.

## 5. Nommer

### Module pur `src/vues/qcm.ts` (tests : `tests/qcm.test.ts`)

```ts
export const NB_CHOIX = 4;
interface LieuQcm { id: string; point: [number, number]; voisins: readonly string[] }
/**
 * Les choix d'une question : la cible et 3 leurres, mélangés. Leurres : ses
 * voisins jouables (3 tirés au hasard s'il y en a plus), complétés par les
 * jouables les plus proches (geoDistance entre points d'étiquette, puis id)
 * ; jamais la cible, jamais deux fois le même. Lève si moins de 4 jouables.
 */
export function choix(cible: string, lieux: ReadonlyMap<string, LieuQcm>, jouables: ReadonlySet<string>, aleatoire?: () => number): string[];
/** Partie de Nommer : un seul essai par question, le bilan compte les justes du premier coup. */
export class PartieNommer {
  constructor(cibles: readonly string[]);
  readonly courante: string | undefined; readonly numero: number; readonly finie: boolean;
  repondre(choisi: string, temps_ms: number): { juste: boolean };
  bilan(): { justes: number; n: number; temps_median_ms: number | null; fautes: { id: string; choisi: string }[] };
}
/** La zone doit-elle être amenée à l'écran : hors de la partie visible (au-dessus de la barre) ou plus petite que 8 px. */
export function doitCadrer(p: [number, number] | null, taille_px: number, l: number, hVisible: number): boolean;
```

- `jouables` = **toutes** les zones jouables du terrain (monde : les 195
  `statut: 'jouable'`, jamais un territoire, une zone contestée ni le
  paquet optionnel ; un voisin non jouable est sauté). Les leurres ne se
  limitent pas à la série (un pays d'Europe peut avoir la Russie ou la
  Turquie en leurre).
- Tests : pour **chaque** jouable du monde et chaque commune : 4 ids
  distincts, la cible dedans, tous jouables ; île sans voisin (Maurice)
  → 4 choix quand même, les plus proches ; avec ≥ 3 voisins jouables,
  les 3 leurres en sont ; aléatoire fixé → résultat déterministe ; ordre
  de la cible réparti (pas toujours en tête) ; Le Port (2 voisins) → ses
  2 voisins + la commune la plus proche ; `PartieNommer` : une réponse par
  question, bilan, fautes ; `doitCadrer` aux bords.

### Vue (`src/vues/nommer.ts` DOM, appelée par `src/vues/essai.ts`)

- **Interrupteur Localiser / Nommer** : un `.seg` (`#essai-mode`,
  `role="group"`, `aria-pressed`) sous le titre du départ de Toucher,
  au-dessus de la liste ; vaut pour toutes les séries ; gardé dans
  `localStorage` `terramemo.toucher.mode` (`localiser` par défaut, même
  try/catch que la série) : le pilote, profil neuf, reste en Localiser.
- Question : `carte.effacerMarques()`, `carte.marquer(id, 'choisi')`
  (accent : les quatre rendus le savent), et, si la zone fait moins de
  12 px à l'écran, `carte.anneau(id, 'choisi')` (micro-États, petites
  îles). Si `doitCadrer(carte.ecran(id), tailleEcranPx(…), l, haut de la
  barre)` : `carte.montrer(id)` (vol borné à 40 dans le monde, 4 sur
  l'île). Sur l'île au zoom 1, rien ne bouge (tout est visible et ≥ 22
  px) ; dans le monde au zoom 1, seuls les petits pays et ceux hors champ
  font voler la carte. Les touchers sur la carte ne répondent pas
  (`toucher()` sort tout de suite) ; glisser et pincer restent libres.
- **Barre `#barre-nommer`** (`.carte-barre.essai`), de haut en bas :
  consigne (`consigne_nommer` du terrain) et compte « 3 / 24 » ; **grille
  2 × 2 de boutons** (`.nommer-choix`, `grid-template-columns: 1fr 1fr`,
  `gap: 8px`, `min-height: 48px`, texte sur deux lignes au besoin :
  « Saint-Vincent-et-les Grenadines » tient en ~166 px) ; rétroaction ;
  « Terminer ». ~210 px de haut à 384 px, sous le pouce ; la marge basse
  de l'île (30 % de 723 = 217 px) la garde hors de l'île.
- Réponse (un seul essai) : boutons désactivés ; juste → bouton et zone
  en vert (`.juste`) ; faux → bouton choisi en rouge (`.faux`), bon
  bouton en vert, zone demandée en vert et zone choisie en rouge sur la
  carte (`marquer(choisi, 'faux')` : on voit où elle est) ; puis question
  suivante après **900 ms (juste) / 1 800 ms (faux)** (les pauses du
  Chrono). Un « juste » en attente quand on quitte la vue compte (même
  logique que `validerEnAttente`).
- Bilan (`#essai-bilan`) : titre « Nommer · {série} », `bilan_nommer`,
  temps médian, liste des fautes (`bilan_nommer_faux`), « Recommencer »
  (retour au départ, monde). Les données des choix (`lieux`, `jouables`)
  viennent du terrain : `t.donnees.entites` et `t.jouables`.

## 6. Chrono de La Réunion

- Épreuve **`chrono:localiser:reunion`** (`idEpreuve(SERIE_REUNION)`).
- Barème (src/epreuve/bareme.ts) :

```ts
/** Échelle des réponses fausses par terrain : 500 × e^(−d / échelle). */
export const ECHELLES_KM = { monde: 300, reunion: 5 } as const;
export const ECHELLE_KM = ECHELLES_KM.monde;
export function pointsQuestion(r: ReponseChrono, delai_ms: number, echelle_km = ECHELLE_KM): number;
```

  `PartieChrono(cibles, delai_ms, echelle_km = ECHELLE_KM)` (chrono.ts)
  passe l'échelle à `pointsQuestion` et `scoreEpreuve`. La vue :
  `new PartieChrono(melanger(ids), DELAI, ECHELLES_KM[serie.terrain])`.
  Délai : 15 s comme le monde (à caler sur le téléphone ; les règles
  bornent à 15 s par question).
- **`VERSION_BAREME` reste 1** : la formule du monde ne change pas (ses
  scores publiés restent comparables), l'épreuve de l'île est neuve
  (aucun score à invalider), et les règles bornent déjà une erreur à 500
  points quelle que soit l'échelle. Changer la version viderait les
  records locaux (`lireRecords`) et serait refusé par les règles
  (`bareme == 1`).
- Record local : inchangé (`enregistrerPartie` par id d'épreuve).
  Classement de l'épreuve et général : `blocClassement(epreuve, …)` est
  déjà générique ; `publierTout` et `totalGeneral` parcourent les records
  de l'appareil, l'île y entre d'elle-même. **Rien à changer dans
  `src/vues/classement.ts`** (il n'y a pas de liste d'épreuves).
- `firestore.rules` : `'chrono:localiser:reunion': 24` dans `tailles()`,
  général `n <= 414` (390 + 24), commentaires à jour (195 pays + 24
  communes). Tests (`tests/regles.test.ts`, `npm run test:regles`) :
  l'île à 24 questions acceptée, 23 et 25 refusées ; bornes du barème
  sur l'île (23 justes + 1 erreur : 23 000 à 23 500) ; général 414

  firestore`) : avec les anciennes, un record de l'île serait refusé sans
  bruit (`publier` rend `false`) et un général complet (> 390 questions)
  aussi.
- Tests (`tests/bareme.test.ts`, `tests/chrono.test.ts`) : échelle 5 km

## 9. Risques et pièges lus dans le code

- **« Pays » partout** : le champ `Entite.pays` porte une commune (gardé
  pour ne pas toucher ~140 lignes, commenté dans types.ts) ;
  `LIBELLE_STATUT`, `vueSaisie` (filtre `statut`), `series()` (lit
  `continent`), `maillage.worker.ts` (lit `pays.json`) restent du monde
  seul : ne jamais leur passer les données de l'île. Textes en dur dans
  essai.ts (« Touche : », « Le bon pays est en vert », « Voir »,
  « Passer », bilan) : ceux que le terrain change passent dans
  `textes.fr.json`, les autres aussi tant qu'on y est (décision
  « Langue »).
- **`nomDe(ctx, id)`** lit les noms du monde : sans changement, une
  commune s'affiche « 97407 ».
- **Tests existants** : `tests/carte-vues.test.ts` fige les 8 séries de
  `series()` (d'où la série de l'île ajoutée hors de `series()`) ;
  `tests/chrono.test.ts` fige les 7 séries du Chrono (à mettre à jour,
  unité D) ; `tests/regles.test.ts` fige le général à 390 (unité B) ;
  `tests/donnees.test.ts` vérifie l'empreinte de `build.mjs` (ne pas le
  modifier) et les fichiers du monde dans `public/geo/` (ne pas mettre ceux de
  l'île à la racine de `geo/`).
- **Sens des anneaux** : la sortie GeoJSON de mapshaper suit la RFC 7946
  (antihoraire) que d3 lit comme le complément ; sans `polygones()`, la
  projection ajustée et `geoContains` sont faux sans erreur visible.
- **Ordre des axes du WFS** (lat, lon en EPSG:4326) ; **UTM 40S** de
  l'archive REU (reprojeter) ; archive ADMIN EXPRESS de la France
  entière (~500 Mo) : prendre l'archive du territoire REU ou le WFS.
- **`Carte.rendre()` sur un hôte sans taille** prend `window.innerWidth
  / innerHeight` : créer et insérer l'hôte (visible ou en `visibility:
  hidden`, jamais `display: none`) avant `rendre()`.
- **Constantes du monde dans `Carte`** : `ZOOM_MAX` (400) dans
  `scaleExtent` et `garderVue`, `ZOOM_MAX_MONTRER`, `limiter` sur la
  sphère, `fabriqueTraces(nom)` : toutes à lire dans le cadre, sinon
  l'île zoome à 400 ou se déplace hors de l'écran.
- **Pastilles** : `micro: true` donnerait un disque à presque toutes les
  communes (seuil de 1 000 km²) ; `cadre.pastilles: false` en plus.
- **Ordre du DOM** : l'hôte de l'île inséré après les barres les
  couvrirait (elles sont ajoutées après `#carte`) : `hoteMonde.after()`.
- **Pilote** : `window.terramemo.carte` doit rester le monde (mesures,
  `ui` qui joue l'Amérique du Sud) ; le mode Nommer gardé dans le
  navigateur ne doit pas être le défaut (captures `3-` et `4-`) ;
  `contexteMesures` et `mesures.chargement` décrivent le monde.
- **Chrono** : lancer la jauge avant la fin du chargement de l'île
  volerait du temps ; `desactiver` doit remontrer le monde (le routeur
  le fait aussi) ; `fmtKm` arrondi à l'entier affichait « 0 km ».
- **Règles** : à déployer avant le site (§ 6) ; `bareme == 1` interdit de
  changer `VERSION_BAREME` sans migrer les règles et les classements.
- **Quota** : aucun `preload` ni prefetch de l'île ; les `.json` sont en
  `no-cache` (firebase.json) : une revalidation (304) par visite qui
  ouvre l'île, négligeable.
- **Deux sessions** : `src/carte.css` et `src/vues/textes.fr.json` sont
  touchés par C puis D, `tests/chrono.test.ts` par B puis D : jamais en
  même temps (phases).
